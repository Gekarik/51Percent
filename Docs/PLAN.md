## Известные баги

- ✅ `NullReferenceException: Outline.SmoothNormals` — добавлен null-guard на `MeshFilter.sharedMesh` в `LoadSmoothNormals()`
- ✅ `NullReferenceException: OwnershipTracker.Initialize` — `HexGrid` помечен `[DefaultExecutionOrder(-50)]` (инициализируется до `TerritoryManager`) + defensive null-checks в `OwnershipTracker.Initialize`
- ✅ `UnassignedReferenceException: HexView._meshFilter` — следствие предыдущего фикса: `HexGrid.Awake(-50)` запрашивал границы меша раньше `HexView.Awake(0)`. Убрана временная связанность — `MeshRenderer`/`MeshFilter` в `HexView` стали ленивыми геттерами

## Эпик 1 — Система бустеров

- ✅ Архитектура бустеров (Booster, BoosterHandler, IBoosterContext, IBoosterEffect, IBoosterObservable)
- ✅ BoosterSpawner
- ✅ Активация бустера по кнопке (Player хранит эффект, активирует Space; Enemy — немедленно)
- ✅ BoostViewer в HUD (иконка + таймер активного бустера)
- ✅ Leaderboard: иконка бустера у каждого персонажа (карман или активный — единая иконка)
- ❌ HUD: индикатор подобранного бустера + подсказка кнопки активации
- ❌ Сброс бустера из кармана по кнопке (доменная операция `BoosterHandler.DropPending()` готова, нужен только input у Player)
- ❌ Визуал крыльев на спине при активации WingsBooster
- ⚙️ Анимации движения на время эффекта (скейт у Speed, медвежья походка у Mushroom): механизм готов — BoosterAnimationSwitcher на вьюшке слушает BoosterChanged, мапит BoosterId → LocomotionMode через BoosterAnimationRegistry и выставляет int-параметр аниматора; осталось в контроллере персонажа добавить параметр LocomotionMode, состояния походок и переходы (crossfade в графе), заполнить реестр

**По ГДД:**
- ✅ SpeedBooster — ускорение персонажа
- ✅ WingsBooster — воскрешение при смерти, respawn на свою территорию
- ⚠️ SpikesBooster — реализован как инверсия убийства по трейлу (одноразовый, со сменой меша трейла); по ГДД должен замедлять врагов на своей территории
- ❌ MeteorBooster — рандомная точка карты становится нейтральной (решено: делаем, пятый и последний бустер)
- 🚫 EarthquakeBooster — отменён: с правилом «один бустер на руках» боты не держат бустеры в кармане, эффект был бы невидим

**Авторские добавления (не в ГДД):**
- ✅ MushroomBooster — увеличивает модель, расширяет захват за шаг; широкий захват режет чужой трейл через общий kill-pipeline (в ГДД это пассивная механика роста)
- 🚫 TrailCutterBooster — отменён: снаряд + прицеливание = новый тип управления, вне бюджета
- 🚫 CaptureRakeBooster — отменён: дублирует роль MushroomBooster

**Спавн:**
- ❌ Зона спавна коллектиблов: выделить внутренний collider/inset чтобы предметы не появлялись у края карты

**Дизайн-решение:**
- ✅ Стакинг бустеров решён: правило «один бустер на руках» — пока есть бустер в кармане или активный, новый не подбирается (`BoosterHandler.CanAccept`). Непринятый бустер остаётся на поле.

**AI:**
- ✅ Боты не преследуют бустер, когда руки заняты (типизированный реестр коллектиблов + `CanAcceptBooster`)
- ❌ AI: учёт активного бустера в стратегиях

## Эпик 8 — Архитектурные улучшения

- **State pattern для EnemyBrain** — заменить enum BotState + switch на IEnemyState { Enter(); Execute(); Exit(); }. EnemyBrain становится контекстом, состояния сами инициируют переходы через TransitionTo(). Цель: добавление новых AI-состояний без регрессий.
- **CharacterFactory** — выделить конструирование персонажа из CharacterSpawner в отдельный класс. Spawner остаётся координатором (регистрация в WinConditionTracker, LeaderBoard, KillManager). Цель: respawn, dynamic spawning без дублирования логики.
- **Bootstrap → Module Installers** — разбить Bootstrap на GridInstaller, CharacterInstaller, AIInstaller. Bootstrap только оркестрирует порядок Install(). Цель: предотвратить God Object при росте систем.

> Ограничение: без статики — платформа WebGL (Яндекс Игры).

## Воскрешение

- ✅ PlayerRespawner: смерть игрока → задержка → новый персонаж через фабрику спавнера (кол-во жизней, задержка, длительность приземления — сериализованы)
- ✅ События `RespawnStarted` / `RespawnFinished`: между ними персонаж выключен из взаимодействий (Mover/Grabber/Conqueror) — окно под анимацию приземления
- ✅ RespawnShieldBuilder: кольцо невидимых стен вокруг точки респавна на время приземления
- ✅ WinConditionTracker не завершает игру, пока есть ожидающий респавн (IRespawnTracker)
- ✅ Монеты за жизнь — автоматически: новый персонаж = новая статистика, старые монеты рассыпались при смерти
- ⚙️ Анимация приземления с неба: механизм готов — RespawnLandingAnimator (Init из Bootstrap) через IRespawnNotifier слушает RespawnStarted/RespawnFinished, опускает вьюшку с _startHeight за LandingDuration и держит bool-параметр аниматора IsLanding; осталось: компонент в обе сцены + ссылка в Bootstrap, в контроллере параметр IsLanding + состояние Landing (клип T-pose) + переходы
- ❌ Кошелёк после конца игры (Эпик 4)
