# Словарь терминов проекта

Составлен 20 сентября 2026 по фактическому коду после рефакторинга механик — это первый пункт
чеклиста нейминга (пункт 13 [аудита](architecture-review-2026-09-17.md)). Словарь фиксирует, как
называются вещи **сейчас**, и отдельно собирает кандидатов на переименование.

**Переименования не выполнены.** Аудит требует согласовать термины до правок, а сами
переименования проводить малыми проверяемыми шагами с сохранением `.meta`/GUID, сериализованных
полей и строк в редакторских инструментах. Здесь только предложения с обоснованием.

## Термины предметной области

| Термин | Что означает в игре | Где живёт в коде |
| --- | --- | --- |
| Участник матча | Игрок или бот, занимающий территорию и способный погибнуть | `ICharacter`, `CharacterBase` |
| Клетка | Шестиугольник поля; хранит владельца и своё состояние | `Hex`, `IHex`, `HexCoord` |
| Закреплённая территория | Клетки в состоянии `Busy`, принадлежащие участнику | `TerritoryManager`, `OwnershipTracker` |
| Трейл | След за пределами своей территории; пересечение чужого трейла убивает его владельца | `TrailRun`, состояние `HexState.PartOfTrail` |
| Захват | Закрытие трейла возвратом на свою территорию: замкнутая область переходит участнику | `TrailRun.Enter` → `TerritoryManager.CaptureEnclosedArea` → `ConquestAlgorithm` |
| Фрагмент | Часть территории, отрезанная чужим захватом; сохраняется только крупнейшая | `TerritoryManager.ReleaseDisconnectedFragments` |
| Выбывание | Обязательная последовательность после смерти: смерть, убийство, респавн, монеты, лидерборд | `CharacterElimination` |
| Бустер | Подбираемый предмет и создаваемый им эффект; применяется сразу при подборе | `Booster`, `IBoosterEffect`, `BoosterHandler` |
| Окно приземления | Время после появления, пока участник не играет | `LandingWindow` |
| Фаза матча | Running / Paused / Finished | `MatchState` |

## Соглашения, сложившиеся в коде

- **Модель** — обычный C#-объект с правилами и состоянием, без Unity-сцены: `BoosterHandler`,
  `LandingWindow`, `TrailRun`, `PlayerStats`, `CharacterStats`, `MatchState`. Время получает
  от владельца через `Tick(deltaTime)`, поэтому на паузе не идёт.
- **Адаптер** — MonoBehaviour, связывающий модель со сценой: `Conqueror` (положение),
  `EnemyBrain` (наблюдения для AI), `Mover` (Rigidbody).
- **Презентация** — отображение состояния: `BoosterPresentation`, `CharacterView`, `HexPresenter`.
- **Биндер** — подписчик на появление участника, раздающий ему презентацию или поведение:
  `PlayerHudBinder`, `EnemyBrainBinder`.
- `Try*` возвращает `bool` и ничего не делает при отказе; события в прошедшем времени сообщают
  о состоявшемся результате (`BoosterEnded`, `AreaCaptured`, `Consumed`).

## Кандидаты на переименование

Порядок — по тому, насколько имя мешает читать код.

| Сейчас | Предложение | Почему |
| --- | --- | --- |
| `PlayerStats` | `MatchScore` или `CharacterScore` | Хранит монеты и убийства, есть и у ботов — «Player» вводит в заблуждение. Рядом живёт `CharacterStats` с совершенно другим смыслом |
| `CharacterStats` | `CharacterAttributes` | Это скорость и ширина захвата с модификаторами, а не счёт. Пара `PlayerStats`/`CharacterStats` — главный источник путаницы в именах |
| `BoosterHandler` | `BoosterSlot` или `ActiveBooster` | «Handler» не говорит ни о чём; класс владеет активным эффектом и его сроком |
| `KillManager` | `TrailCombat` | Отвечает за исход атаки по трейлу, а не «управляет убийствами» |
| `TerritoryManager` | `Territory` | «Manager» ничего не добавляет: класс и есть территория поля |
| `Conqueror` | `CellTracker` или `PositionReporter` | После пакета 22 это адаптер положения, завоеванием занимается `TrailRun` |
| `CollectibleSpawnerBase` | `CollectibleSpawner` | Суффикс `Base` дублирует `abstract` |
| `ICollectibleConsumer` | `IItemReceiver` | «Consumer» и `Consumed` теперь означают разное: приём предмета и его потребление |
| `VectorProviderComponent` | `MoveCommandSource` | Возвращает направление движения, а не абстрактный вектор |

Не трогать без отдельной причины: `Hex`, `HexCoord`, `TrailRun`, `MatchState`, `LandingWindow`,
`CharacterElimination`, `SpawnHexSelector`, `TrailThreatEvaluator`, `TerritoryBearings` — эти
имена уже отражают роль.

## Папки и namespaces

Namespace в проекте нет ни одного: весь игровой код лежит в глобальном пространстве сборки
`51Percent.Runtime`. Раскладка по папкам (`Entities`, `Gameplay`, `Core`, `AI`, `UI`, `Spawners`,
`Grid`, `Interfaces`) осмысленная, но `Interfaces` собирает контракты разных механик в одном
месте — их естественное место рядом с потребителями. Вводить namespaces имеет смысл вместе с
этим переносом, одним согласованным шагом, иначе `using` придётся править дважды.
